## 一、社区共识：先做幕僚长，再拉专家队

几乎所有高赞教程（Alex Finn、Matthew Berman、Nate Herk、Brock Mesarich 等）都独立讲到同一套玩法：

1. 第一个 Bot 设成 **Chief of Staff（幕僚长）**，置顶
2. 你平时只跟幕僚长说话
3. 让它拆任务、建专家 Bot、在群聊里交接
4. 外发、花钱、删除等不可逆动作必须先问你

入门口令（多次出现的套路）：

> 把我是谁、我在干什么、常用工具一口气倒给它，然后问：  
> 「你会怎么帮我配置 Grok Bot？先出计划，我批准后再建团队。」

出处综合：aibuilderclub 对四支高播教程的转写汇总；官方也写过「幕僚长 + 各专线专家」的组织图。

## 二、@ridark_eth：组织图，而不是待办清单

原帖标题大意：*I gave Elon Musk's new Grok Bot an org chart instead of a to-do list…*

**核心观点**：别把 Grok Bot 当更聪明的对话框，而是当成一张你能拥有的组织图。

推荐阵容（可抄改）：

| 角色 | 职责要点 |
|---|---|
| Atlas（幕僚长） | 你唯一对话的入口；给「结果」不给琐碎任务；早发计划、晚发交付；花钱/不可逆才找你 |
| Scout（研究） | 找并验证 ICP；每天固定数量线索 + 一行「为什么现在需要我们」+ 来源；验证不了就标未验证 |
| Quill（内容） | 本周学到的 → 5 帖 + 1 长文；对齐你最近写作语气；只出草稿、永不发布 |
| Pitch（外展） | 给 ready 线索写首封 + 两封追踪；≤60 词；进草稿箱批量核准 |
| Vault（收件箱/运营） | 分三类：需要我 / 需要某 Bot / 不需要；后者自处理，前者早上 9 点前五点汇报 |
| Ledger（分析） | 每晚一份：动了什么、没动什么、明天只盯一个数字 |

接线规则：

- **按结果建群聊**，不是按人头建群；幕僚长坐进所有群
- 每个岗位描述末尾必须有硬边界：`Never do this without asking`
- **示范一次，不要空讲**：屏幕录制完整流程，比一页说明书管用

公开出处：X @ridark_eth；中文整理页 usegrokbot.com

## 三、@zodchiii：十分钟搭一支「无人公司」

做法极简：

1. 只建一个叫 **Chief of Staff** 的 Bot
2. 把章程整段贴进 **Description（描述栏）**——描述栏就是全部配置
3. 告诉它要协调哪些角色（研究 / 写作 / 运营……）
4. 接上账号权限，以后只对幕僚长下令

可复制章程（社区复原版，非逐字原文）：

```text
Role: Chief of Staff. You are my single entry point to a team of Grok Bot agents.
I talk only to you; you coordinate the rest.

Mission: Take whatever I ask for, figure out which role should handle it,
delegate, and come back to me with the result or the one decision you need.

The team you coordinate (edit to your own):
- Researcher — gathers facts and options.
- Writer — turns decisions into drafts.
- Ops — handles scheduling, tracking and follow-ups.

How to work:
- Break goals into jobs, assign roles, manage hand-offs.
- Report: what is done, what is blocked, what only I can decide.
- Keep one running view of what the team is working on.

Never, without asking: send an external message, publish, spend money,
or delete anything. Never invent facts or numbers.
```

公开出处：X @zodchiii；复原页 grokbot.dev/use-cases/team-in-10-minutes

## 四、Nate Herk：一周九条使用课

视频/文章：*A Week of Grok Bot Lessons in 10 Mins*（X 高浏览）

常见提炼（社区转述）：

1. 先有幕僚长，再扩编
2. 用 **Teach a task（屏幕示范）** 教浏览器流程，比纯文字提示稳
3. 研究 / 内容 / 跑腿类任务最容易出结果
4. 描述栏写「常驻规则」，对话里写「今天的任务」
5. 自动化（Routine）放最后：先手动跑通两次

Elon 曾公开引用并询问大家在跑什么 Bot。

## 五、Alex Finn：简单实用，先建 CEO 再让它招人

中文社区广泛转述的要点：

- 不纠结选模型、上下文、权限面板——主打开箱即用
- 每个 Bot 有云端电脑；可用 Agent Mail 等给 Bot 独立邮箱身份
- Bot 之间默认能互发消息、共享上下文
- 建议：置顶一个 CEO / 幕僚长，把背景和目标倒给它，**反向让它规划并创建其他 Bot**
- 与本地深度定制工具（如 Hermes）是互补，不是替代

公开出处：Alex Finn 教程视频与相关 X 讨论；新浪等中文转载

## 六、Krista Letz / 内部 GTM 玩法（X 长文）

SpaceXAI GTM 相关公开分享常见结构：

- 约十个 Bot，上面钉一个幕僚长
- 邮件：收件箱 + 会后草稿
- 会议：Salesforce / Gmail / Slack / 通话记录拼每日会前简报
- 内容：幻灯片类 Bot（如 Figma）
- 研究：线索与市场信号

启示：先钉住「对你说话的那一个」，再按业务线扩编。

## 七、构建者长文里反复出现的规矩

综合约十余篇 X Article / 长帖（Cursor / SpaceXAI 员工与付费用户）：

1. **Chat 是历史，文件才是记忆**——重要状态写到共享工作区文件
2. **先任务 → 再 Skill → 最后 Routine**，中间要 Test run
3. **描述末尾必须有围栏**（send / spend / publish / delete 须审批）
4. **账号共享一台云电脑**：Bot 不是安全边界，别指望用「多 Bot」隔离登录态
5. 编码场景：Grok Bot 更适合当「外环调度」，真正写码常转 Cursor Cloud Agent
6. 额度：聊天过碎、Routine 全天跑、一次性扫十年邮箱，最容易烧爆周额度

出处综合：aibuilderclub《How to Use Grok Bot》对十九篇 X Article 的核对摘要

## 九、上手清单（把推文收成可执行步骤）

1. 安装桌面端或手机端 → Cursor 账号登录 → 等云电脑就绪  
2. 建第一个 Bot：命名幕僚长 → 描述栏贴章程 + Never 列表  
3. 大脑倾倒：身份、目标、工具、禁忌  
4. 让它出团队方案，你批准后再建专家 Bot  
5. 接插件：邮件 / 日历优先；X 可后接  
6. 派一件只读真活（总结 PDF / 整理线索），验收后再教 Routine  
7. 敏感操作自己接管输入密码；外发前必须审批
